  1. 01

    Document validation with Vision AI

    Live

    University admission files were reviewed by hand, roughly 14 minutes per document. The system reads each one with GPT-4o Vision, applies deterministic business rules, cross-checks the identity number across every document in the file to flag possible impersonation, and drafts the applicant notification. About 5 seconds per document, with a full audit trail.

    The design point: AI extracts, rules decide. When the model's own confidence drops, the file escalates to a human instead of guessing.

  2. 02

    The assistant on the front page

    Live

    A RAG system that answers questions about my profile using only my actual documents, cites the exact source of every claim, and says so when the answer isn't there instead of inventing one.

    Pure vector search failed on the most obvious question — "does he know Python?" didn't retrieve the project built in Python, because the term is diluted across a chunk about something else. Keyword search fixes exactly that, so retrieval is hybrid: BM25 and embeddings, fused by rank.

    It started on ChromaDB and ended without a vector database: at 37 documents the embeddings fit in 222 KB and the search is one matrix multiplication. It now runs as a serverless function on this domain.

    Python · numpy · BM25 · OpenAI · Vercel Try it How it works Source
  3. 03

    Catalog diagnostics between ERP and storefront

    2026

    Odoo 19 across three countries, with Shopify, Amazon, TikTok Shop and Mercado Libre on top — and a single developer for all three. The business was deciding on data the system didn't reflect: unreal inventory balances, orders that never arrived, catalogs drifting apart. I built a Python diagnostic that runs eleven checks between Odoo and Shopify every two days, in under three minutes, and returns a workbook where every row says what to do and links straight to the record that needs fixing.

    It caught a connector failure that had gone a week unnoticed, with orders worth tens of thousands of dollars invoiced and never delivered. The maintenance programme it supported closed 48 SKUs in three weeks and took broken cross-system mapping to zero. And it separated symptom from cause: the backlog wasn't shrinking because new cases arrived at the same rate, all of them traced to one manual-entry practice.

    The design point: the auto-fix mode has deliberately low ceilings — ten changes per run, three per product, and only against the storefront, never the ERP. If a batch exceeds them it isn't scattered typos, it's a catalog problem, and a person should look at it. It backs up and logs every change before touching anything, so every correction is reversible.

    Python · Odoo XML-RPC · Shopify Admin API · openpyxl Client system
  4. 04

    UTM attribution engine over a CRM

    2026

    Campaigns were being judged on gut feeling: the same channel reached the CRM under five different labels, so reports couldn't be aggregated. Meta Ads arrived as "Social media" with nothing marking it as paid; organic and paid Instagram traffic looked identical; QR scans from physical billboards came in with no parameters at all. I wrote a ~300-line JavaScript classification engine that resolves each case from contextual signals and normalises twelve UTM fields per event — six first-touch, six last-touch.

    Three more flows covered what the CRM couldn't: splitting a multi-apartment opportunity into one per unit, cloning opportunities across pipelines with 40+ custom fields, and routing each survey response to the right opportunity without duplicating it. The hardest find: opportunities created by automation inherited the triggering user's permissions, and without access to the target pipeline they failed silently.

    n8n (self-hosted) · JavaScript · GoHighLevel REST API Client work

  6. 06

    Meeting agent, board and MCP server

    2026

    The recording platform's auto-summary wasn't a basis for decisions. Speaker labels came scrambled, so a commitment could land on whoever didn't make it; conditional agreements — "we do it if the resource is dedicated" — were summarised as settled ones; and the most valuable thing, an old blocker finally closing, got mentioned in passing and vanished.

    I built all three pieces: an agent that reads the full transcript and never the summary, the board where state lives, and the MCP server the agent writes through. Every open item lands with an owner, a hard date and a status from a closed vocabulary. It processed around 180 meetings over seven months and carried the management of the ERP project above, across more than twenty people spanning business, development and leadership. The result isn't a pile of loose summaries: it's a project history you can walk back through.

    The design point: when the agent finds a contradiction between what was said and what's on record, it doesn't pick the likelier version — it flags it for a human. Whoever reads the board trusts it and won't re-check the detail, so a silent error isn't caught: it resurfaces as a badly informed decision weeks later.

    Next.js 15 · Supabase · mcp-handler · Fathom API Private repository
