How the assistant works

The robot on the front page isn't a widget I installed. It's a system I built, and it's part of the portfolio — arguably the most honest part, because you can check whether it's telling you the truth.

What it is

It's a RAG system — Retrieval-Augmented Generation. The idea is simple: instead of asking a language model what it happens to remember, you first go find the relevant passages in a set of real documents, hand those to the model, and ask it to answer using only that.

The difference matters. A general chatbot asked about my experience would produce something plausible — and plausible is exactly the problem. This one can only repeat what's actually written in my CV and project notes, and it tells you which file and which section each statement came from.

When the answer isn't in those documents, it says so. That behaviour is deliberate and it's the hardest part to get right: the natural tendency of these models is to fill the gap with something reasonable-sounding.

What happens when you ask it something

01
Your question is rewritten

Follow-ups like "and what year was that?" mean nothing on their own. A small model turns them into a complete, standalone question first, using the conversation so far — otherwise the search would look for those literal words and find nothing.

02
Two searches run at once

One matches by meaning, so "has he led teams?" finds a passage about coordinating developers even without those words. The other matches exact terms, which is what catches "Odoo" or "GoHighLevel". Their results are merged by rank.

03
The passages become the answer's only source

The retrieved fragments go to the model with strict instructions: use nothing else, respect the nuances in the text, cite every claim, and say plainly when the documents don't cover the question.

04
Only the sources actually used are shown

The search returns five candidates; the model usually uses one or two. Listing all five as "sources" would suggest the answer came from all of them, so the rest are filtered out.

Don't take my word for it — check it

The documents the assistant reads are public, in the same repository as the code. So you can do something you can't do with an ordinary portfolio: read the source material, then ask the assistant about it and see whether the answers hold up.

Try asking about something that isn't there — a technology I've never touched — and watch it decline instead of improvise. That test says more about the system than any answer it gets right.

Built with

Python, with ChromaDB as the vector database, rank-bm25 for keyword search, and OpenAI's API — text-embedding-3-small to index the documents, gpt-4o to write the answers and gpt-4o-mini for the cheaper rewriting step. The interface is Streamlit, and it's embedded in the front page of this site.

No RAG framework. Every piece is written by hand — which is how I found the problem below, and probably wouldn't have with a pre-packaged pipeline.

The bug worth mentioning

The first version used semantic search only, and it failed on the most obvious question you could ask it: "does he know Python?" didn't retrieve the project I'd built entirely in Python.

The reason is that the passage describes a document-validation system — vision models, business rules, identity checks. The word "Python" appears twice in about a hundred and twenty. Its overall meaning points at "validation system", not at "Python skills". No amount of clever querying fixes that, because the problem is in the document, not the question. Keyword search fixes it instantly, because a technology name is a rare term and weighs heavily.

I also tried a well-known technique for this called HyDE and dropped it, with measurements: it made the similarity scores look better while making the actual results worse. Good numbers, wrong answers — a useful reminder that the metric isn't the goal.

What it doesn't have

No automated evaluation suite. I test with a fixed set of questions covering the cases I care about, but I run them by hand — which is how a real defect slipped past me once and got caught by accident. It's the first thing I'd build if this were serving anyone but me.
